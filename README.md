# 모모플랜 브로드밴드

<p align="center">

모모플랜은 원하는 월 요금, 데이터, 통신망과 혜택을 대화로 입력하면 조건에 맞는 요금제를 찾아주는 웹 서비스입니다.<br>
SKT·KT·LG U+와 알뜰폰 요금제를 한곳에서 검색하고 비교할 수 있습니다.<br>
가장 적합한 요금제 3개와 추천 이유, 현재 요금제 대비 12개월 예상 비용 차이를 함께 보여줍니다.

> ASAC 빅데이터 분석가 11기 브로드밴드 최종 프로젝트 · 2026.07–2026.09<br>

## 프로젝트 개요

| 항목 | 내용 |
|---|---|

| 주요 사용자 | 통신비를 줄이거나 현재 요금제를 변경하려는 사용자 |

## 문제 정의

통신 요금제는 기본 데이터, 소진 후 속도, 통화·문자, 테더링, 할인 기간과 OTT 혜택처럼 비교해야 할 조건이 많습니다. 같은 ‘무제한’ 표현도 실제 제공량과 QoS 속도에 따라 체감이 다르고, 단기 할인가만 보면 장기 비용을 잘못 판단할 수 있습니다.

모모플랜은 다음 과정을 하나의 서비스로 연결했습니다.

1. 자연어 대화에서 예산과 사용량, 필수 조건과 선호 조건을 구분합니다.
2. 조건을 만족하지 않는 요금제를 먼저 제외합니다.
3. 남은 후보를 가격·데이터·QoS·혜택·통화·테더링 기준으로 평가합니다.
4. 추천 이유와 12개월 비용 차이를 생성하고, 설명에 잘못된 금액이나 과장된 표현이 없는지 검증합니다.

## 주요 기능

### 전체 요금제 탐색

- 통신사, 월 요금, 데이터 제공량, 통화, 네트워크, 혜택 필터
- 카드·표 보기 및 가격·데이터 기준 정렬
- 요금제 상세 정보와 할인 종료 후 요금 확인

### 요금제 비교

- 관심 있는 요금제를 비교함에 담아 한 화면에서 비교
- 원하는 요금제를 기준으로 다른 상품과의 스펙 차이 확인
- `다른 항목만 보기`로 서로 다른 조건만 모아서 확인

### AI 맞춤 추천

- “월 3만 원 이하, 데이터 100GB 이상”과 같은 자연어 조건 해석
- 현재 요금제를 입력하면 추천 요금제와의 요금·데이터·혜택 차이 비교
- 필수 조건이 부족하면 임의로 추천하지 않고 추가 질문
- 추천 요금제 Top 3와 각 요금제를 추천한 이유 제공

### 추천 설명 검증

- AI가 이해한 예산·데이터·혜택 조건이 사용자의 실제 요청과 일치하는지 확인
- 추천 카드에 표시된 월 요금과 12개월 총비용, 현재 요금제와의 차이가 실제 계산 결과와 일치하는지 확인
- 데이터로 확인할 수 없는 속도 보장이나 위약금 등의 내용을 추천 이유에 포함하지 않도록 제한
- 설명에 오류가 있으면 한 번 다시 작성하고, 그래도 검증되지 않은 문장만 제거해 나머지 설명은 유지

### 추천 파이프라인

추천 파이프라인은 다음 순서로 동작합니다.

```text
profiling → profile_check → recommend → report → evaluation
```

profiling: 자연어 대화에서 예산, 데이터, 통화, 혜택 등 사용자의 추천 조건을 추출
-profile_check: AI가 추출한 조건이 사용자의 실제 요청과 일치하는지 확인
-recommend: 필수 조건으로 후보를 선별하고 SMAA-2 기반으로 추천 순위 계산
-report: 추천 요금제의 특징과 추천 이유, 현재 요금제와의 비용·데이터 차이 작성
-evaluation: 추천 설명의 요금·총비용·비교 내용이 실제 데이터와 일치하는지 확인하고, 근거 없는 표현을 제거

## 추천 알고리즘

세 가지 방식을 같은 요금제 후보군에서 비교했으며, 실제 서비스에는 지식 기반 추천을 적용했습니다.

| 방식 | 구현 | 설명 | 적용 위치 |
|---|---|---|---|
| 협업 필터링 | `agent/segmentation.py` | 합성 가입 이력을 KMeans 세그먼트로 나누고 세그먼트별 인기 요금제를 추천 | 비교 실험 |
| 콘텐츠 기반 | `agent/cosine_recommendation.py` | 사용자 요구 벡터와 요금제 속성 벡터의 코사인 유사도 계산 | 비교 실험 |
| 지식 기반 | `agent/data.py`, `agent/mcda.py` | 필수 조건으로 후보를 거른 뒤 SMAA-2로 다기준 순위 계산 | 실제 서비스 |

### 서비스에 적용한 지식 기반 추천

모모플랜은 사용자의 명시적 조건을 만족하는 요금제를 먼저 선별한 뒤,  
여러 평가 기준과 가중치의 불확실성을 함께 고려하는 **SMAA-2 기반 다기준 추천**으로 최종 순위를 결정합니다.

#### 1. 자연어 요청에서 추천 조건 추출

사용자가 일상적인 문장으로 입력한 요청을 추천 알고리즘이 계산할 수 있는 조건으로 변환합니다.

예를 들어 사용자가 다음과 같이 입력했다고 가정합니다.

> “월 4만 원 이하이면서 데이터가 100GB 이상이고, 소진 후 속도가 5Mbps인 요금제를 추천해줘. OTT 혜택도 있으면 좋겠어.”

시스템은 이 요청을 다음과 같이 해석합니다.

| 추출 항목 | 해석 결과 |
|---|---|
| 월 예산 | 40,000원 이하 |
| 최소 데이터 | 100GB 이상 |
| 소진 후 속도 | 5Mbps |
| 희망 혜택 | OTT 혜택 |

월 예산, 최소 데이터, 소진 후 속도처럼 반드시 만족해야 하는 조건은 추천 후보를 선별하는 데 사용합니다. OTT 혜택처럼 사용자가 선호하는 조건은 후보들의 적합도와 순위를 계산할 때 반영합니다.

추천에 필요한 정보가 부족하거나 요청이 불분명하면 조건을 임의로 정하지 않고 사용자에게 추가로 질문합니다.
#### 2. 필수 조건으로 후보 선별

예산, 데이터, 통화, 통신망, 필수 혜택처럼 반드시 만족해야 하는 조건을 이용해 전체 요금제에서 추천 후보를 선별합니다.

#### 3. 기준별 적합도 계산

필터링을 통과한 요금제마다 가격, 데이터, QoS, 혜택, 통화, 테더링의 적합도를 0~1점으로 계산합니다. 1에 가까울수록 사용자의 조건에 더 잘 맞는다는 의미입니다.

| 평가 축 | 반영 내용 |
|---|---|
| 가격 | 사용자 예산 대비 월 납부액 |
| 데이터 | 목표 사용량 충족도와 과잉 제공량 |
| QoS | 데이터 소진 후 제공 속도 |
| 혜택 | 요청한 혜택과의 일치도 |
| 통화 | 필요한 통화량 충족도 |
| 테더링 | 테더링 제공량 |

데이터 무제한은 단순한 0/1 값이 아니라 기본 제공량과 소진 후 속도를 함께 고려합니다.  
또한 후보 간 값이 모두 같은 평가 축은 순위에 영향을 주지 않도록 계산에서 제외합니다.

#### 4. 실제 가입 데이터를 이용한 가중치 구성

실제 알뜰폰 가입 데이터에 대해 표준화된 Ridge 회귀를 수행하고,  
이를 300회 부트스트랩해 300개의 가중치 표본을 생성했습니다.

이 표본들은 하나의 고정 가중치만 사용하는 대신,  
가입자별로 중요하게 생각하는 기준이 다를 수 있다는 불확실성을 표현합니다.

문자 제공량은 통화 무제한 여부와 98.1%가 겹쳐 별도의 평가 축에서 제외했습니다.  
두 변수를 함께 사용하면 회귀계수가 서로 상쇄되어 가중치가 불안정해질 수 있기 때문입니다.

#### 5. 사용자 선호도 반영

사용자가 가격, 데이터, QoS 등의 우선순위를 지정하면 해당 평가 축의 가중치를 높입니다.

다만 특정 기준 하나가 전체 추천을 독점하지 않도록 조정된 가중치의 최대 비중을 60%로 제한하고,  
나머지 비중은 다른 평가 축에 다시 배분합니다.

#### 6. SMAA-2 순위 계산

300개의 가중치 표본마다 각 요금제의 종합 점수를 계산합니다.

> **요금제 종합 점수 = Σ(평가 기준별 가중치 × 기준별 효용)**

예를 들어 가격, 데이터, QoS, 혜택 등의 효용에 각 가중치를 곱한 뒤 모두 합산합니다.  
같은 요금제라도 가중치 조합에 따라 순위가 달라질 수 있으며, 300개 조합에서 나타난 순위를 종합해 다음 지표를 계산합니다.

- **1위 수용도**: 300개 가중치 조합 중 해당 요금제가 1위를 차지한 비율
- **기대 순위**: 모든 가중치 조합에서 기록한 순위의 평균
- **Top 3 안정성**: 300개 조합 중 상위 3위 안에 포함된 비율
- **추천 적합도**: 가중합 효용의 평균을 0~100점으로 환산한 값

최종 순위는 기대 순위가 낮은 요금제를 우선하고, 기대 순위가 같으면 1위 수용도가 높은 요금제를 우선합니다.

#### 7. 최종 Top 3 구성

동일한 가입 조건과 혜택을 가진 중복 상품은 하나로 합칩니다.

그다음 순위가 높은 후보 중에서 사업자, 데이터 구간, 소진 후 속도가 지나치게 겹치지 않도록  
다양성을 반영해 최종 Top 3를 화면에 표시합니다.

따라서 모모플랜의 추천 점수는 가입 성공 확률이나 절대적인 품질 점수가 아니라,  
**현재 사용자의 조건과 여러 가중치 시나리오를 함께 고려한 상대적 적합도**를 의미합니다.

## 데이터 수집 및 갱신

`crawler/src/`에서 SKT, KT, LG U+, 모요 데이터를 수집합니다.

```text
수집 → 파싱 → 스키마 검증 → 통합 → 이전 데이터와 변경 비교 → 검증 → 서비스 반영
```

- 사이트별 크롤러를 별도 프로세스로 실행해 한 사이트의 오류가 다른 수집에 영향을 주지 않도록 했습니다.
- 전체 행 수 급변, 특정 사이트 데이터 급감, 중복 ID 등 이상 징후가 있으면 갱신을 중단합니다.
- 크롤링 결과는 먼저 `crawler/data/`에 저장되며, 검증 후 `--promote`를 실행해야 서비스용 `data/`에 반영됩니다.
- 추천 서비스는 고정된 CSV를 읽기 때문에 크롤링 중 데이터가 바뀌어 추천 결과가 흔들리지 않습니다.

## 추천 알고리즘 평가

가상 질문 100개에 대해 각 알고리즘의 상위 5개를 생성한 뒤 LLM이 알고리즘 이름을 보지 않고 평가했습니다. 실제 화면은 상위 3개를 제공합니다.

| 방식 | Precision@5 | Hit@1 | 조건 위반 ↓ | 더 나은 대안 없음 ↑ |
|---|---:|---:|---:|---:|
| 협업 필터링: 세그먼트별 인기 요금제 | 19.0% | 27.0% | 68.8% | 4.5% |
| 콘텐츠 기반: 코사인 유사도 | 18.0% | 19.0% | 61.0% | 1.9% |
| 지식 기반: SMAA-2 무작위 가중치 | 51.6% | 56.0% | 10.3% | 62.3% |
| **지식 기반: SMAA-2 + 회귀계수** | **47.4%** | **68.0%** | **10.1%** | **62.9%** |

최종 방식은 상위 5개 전체 적중률보다 사용자가 먼저 보는 1순위의 정확도를 우선해 선택했습니다.

## 실행 방법

이 프로젝트는 로컬에서 백엔드와 프런트엔드를 각각 실행하는 웹 애플리케이션입니다.

### 1. 실행 환경

- Python 3.11 권장
- Node.js 20 LTS 권장
- OpenAI API Key

### 2. 저장소 복제 및 Python 환경 구성

```bash
git clone https://github.com/ASAC11broadband/telecom-plan-recommendation.git
cd telecom-plan-recommendation

python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

macOS/Linux:

```bash
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 3. 환경변수 설정

저장소 루트에 `.env` 파일을 만들고 API Key를 입력합니다.

```dotenv
OPENAI_API_KEY=your_openai_api_key

# 선택 설정: 지정하지 않으면 아래 기본값 사용
PROFILE_MODEL=gpt-4o-mini
REPORT_MODEL=gpt-4o-mini
EVAL_MODEL=gpt-4o
LLM_CALLS_PER_MINUTE=20
```

`.env`는 Git에 커밋하지 않습니다. 요금제 탐색·필터·비교는 저장된 CSV로 동작하지만, 자연어 추천과 요금제 질문 기능에는 OpenAI API Key가 필요합니다.

### 4. 백엔드 실행

첫 번째 터미널에서 저장소 루트를 기준으로 실행합니다.

```bash
uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

정상 실행 확인:

- Health Check: http://127.0.0.1:8000/api/health
- API 문서: http://127.0.0.1:8000/docs

### 5. 프런트엔드 실행

두 번째 터미널에서 실행합니다.

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 http://localhost:5173 에 접속합니다. Vite가 `/api` 요청을 `http://127.0.0.1:8000`으로 전달하므로 별도 CORS 설정은 필요하지 않습니다.

백엔드를 다른 주소나 포트에서 실행할 때는 프런트 실행 전에 `API_TARGET`을 지정합니다.

```powershell
$env:API_TARGET="http://127.0.0.1:8001"
npm run dev
```

## 크롤러 실행

크롤링은 웹 서비스 실행에 필수는 아닙니다. 저장된 데이터 대신 최신 데이터를 다시 수집하려는 경우에만 실행합니다.

```bash
cd crawler

# 네 사이트 수집부터 통합·검증까지 실행
python src/refresh_plans.py

# 기존 캐시로 파싱·비교만 실행
python src/refresh_plans.py --parse-only

# 검증된 크롤러 최종본을 서비스용 data/에 반영
python src/refresh_plans.py --promote
```

`--promote`는 서비스가 읽는 CSV를 변경하므로 크롤링 검증 결과를 확인한 뒤 실행해야 합니다.
