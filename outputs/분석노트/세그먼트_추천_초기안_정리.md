# 소프트 세그먼트 인기 추천과 전환 근거

## 한 줄 요약

사용자를 하나의 세그먼트에 고정하지 않고, 여러 세그먼트에 대한 **소속 확률**을 계산했다.
각 확률에 세그먼트별 요금제 인기점수를 곱해 합산한 뒤 Top-5를 추천했다.

```text
사용자 입력 → 세그먼트별 소속 확률 → 확률 × 세그먼트별 요금제 인기 → Top-5
```

## 실험 데이터

원본 합성데이터는 알뜰폰 사용자 40,000명의 이용량·예산·필요 조건과, 각 사용자가
가입했다고 가정한 요금제(`source_plan_id`)를 함께 담고 있다. 당시 요금제 스냅샷과
연결 가능한 39,095건(97.74%)을 사용했다.

입력에는 연령, 데이터 사용량, 예산, 통화·SMS 필요량, 데이터·통화·SMS 무제한 필요 여부,
OTT 필요 여부를 사용했다. 성별은 추천 근거에서 제외했다.

## 1. 세그먼트와 소속 확률

사용자 특성을 표준화한 뒤 KMeans로 6개의 세그먼트 중심점을 만든다. 신규 사용자는 각
중심점과의 제곱거리를 계산한다.

```text
dₖ = 사용자와 세그먼트 k 중심점의 제곱거리
P(k | 사용자) = softmax(-dₖ / T)
```

`T`는 학습 사용자에서 가장 가까운 두 세그먼트 사이의 거리 차이를 바탕으로 정한다.
전형적인 경계 사용자가 가까운 두 세그먼트에 대략 80:20으로 나뉘도록 정규화한다.

따라서 한 사람은 다음처럼 표현된다.

```text
A 사용자: S1 72.5%, S3 15.1%, S6 7.4% ...
B 사용자: S1 68.0%, S3 22.0%, S6 6.0% ...
```

여기서 확률은 실제 행동이 발생할 확률이 아니라, 중심점 거리로부터 계산한 **정규화된
세그먼트 소속도**다. 여섯 값의 합은 항상 1이다.

### 현재 모델의 세그먼트 해석

`S1`부터 `S6`까지의 숫자는 KMeans가 임의로 부여한 중심점 번호다. 따라서 학습이 끝난 뒤
각 중심점의 사용자 특성을 보고 아래처럼 사람이 이해할 수 있는 이름을 붙였다. 고정 시드
42로 학습한 현재 모델의 해석은 다음과 같다.

| 번호 | 해석 이름 | 중심점에 가까운 사용자 특성 |
|---|---|---|
| S1 | 통화·문자 무제한 중심형 | 데이터 약 10GB, 통화 무제한 필요 100%, SMS 무제한 필요 98% |
| S2 | 저가 실속형 | 데이터 약 10GB, 예산 약 3,500원, 통화·SMS 사용량은 있으나 무제한 필요는 낮음 |
| S3 | 대용량 데이터·무제한 중심형 | 데이터 약 90GB, 예산 약 18,700원, 통화·SMS 무제한 필요 100% |
| S4 | 데이터 무제한 필요형 | 데이터 무제한 필요 응답이 100%인 희소 그룹(76명) |
| S5 | OTT 필수 중사용량형 | 데이터 약 44GB, OTT 필수·선호 응답 100% |
| S6 | OTT 선호 중고용량형 | 데이터 약 50GB, OTT 선호 응답 100%, 통화·SMS 무제한 필요 약 99% |

즉, **데이터 사용이 많은 그룹은 현재 모델에서 S3**다. `S1`은 데이터 다사용형이 아니라
통화·문자 무제한 성향이 뚜렷한 그룹이다. KMeans를 다시 학습하면 S1~S6의 번호는 달라질 수
있으므로, 발표에는 번호만 쓰지 말고 `S3(대용량 데이터·무제한 중심형)`처럼 이름을 함께 표기한다.

## 2. 세그먼트별 요금제 인기점수

학습 사용자의 가입 요금제도 하나의 세그먼트에 완전히 고정하지 않는다. 각 사용자가 가진
세그먼트 소속도를 해당 요금제의 세그먼트별 가입 기여도로 더한다.

```text
Popularity(요금제 p | 세그먼트 k)
= Σ 사용자 i의 P(k | 사용자 i),  단 사용자 i가 p에 가입한 경우
```

집계 뒤에는 작은 세그먼트나 희소 요금제의 순위가 과도하게 흔들리지 않도록 0.1의 작은
평활화 값을 더해 정규화한다.

## 3. 신규 사용자 요금제 점수

최종 점수는 사용자의 세그먼트 소속 확률과 세그먼트별 요금제 인기점수의 가중 합이다.

```text
Score(요금제 p | 사용자 u)
= Σ [ P(세그먼트 k | 사용자 u) × Popularity(요금제 p | 세그먼트 k) ]
```

예를 들어 S1 성향이 강하지만 S3 성향도 일부 가진 사용자는 S1에서 인기 있는 요금제와
S3에서 인기 있는 요금제를 함께 반영받는다. 하드 세그먼트 방식처럼 “S1이므로 S1 인기
Top-5”로 단정하지 않는다.

## 왜 이 방식이 더 자연스러운가

| 하드 세그먼트 인기 추천 | 소프트 세그먼트 인기 추천 |
|---|---|
| 가장 가까운 세그먼트 하나만 선택 | 여러 세그먼트의 소속도를 함께 사용 |
| 같은 세그먼트면 같은 인기 Top-5 | 성향 비율에 따라 인기점수의 조합이 달라짐 |
| 경계 사용자 정보를 버림 | 경계 사용자의 혼합 성향을 반영 |

## 남은 한계와 전환 이유

소프트 소속도로 바꿔도 최종 점수의 중심은 여전히 **세그먼트별 인기**다. 그래서 성향 비율이
비슷한 사용자는 유사한 인기 요금제로 다시 수렴한다. 예산·필요 데이터량·혜택 우선순위를
요금제 단위에서 직접 맞추지 못하는 한계도 남는다.

고정 시드로 분리한 100명에서 소프트 세그먼트 초기안은 15개의 서로 다른 Top-5 조합을
만들었지만, 96%의 사용자는 다른 사람과 같은 Top-5 조합을 받았다. 하드 세그먼트 방식보다
부드러워졌지만 개인화 추천으로는 충분하지 않다는 근거다.

그래서 세그먼트는 사용자군을 설명하고 후보군을 이해하는 분석 정보로 남기고, 최종 추천은
개별 프로필과 요금제 조건을 직접 비교하는 방식으로 전환했다.

```text
소프트 세그먼트: 사용자군 설명과 초기 후보 이해
개인화 추천: 사용자별 필요 조건을 직접 반영한 최종 순위
```
